# 架构与开发边界

```text
浏览器（React 中文 UI）
    │ /api/*
    ▼
Nginx / Vite 代理
    │ /api/v1/*
    ▼
Go Gin API ─────── SQLite（第一阶段 Run、Trace、审批等业务数据）
    │               MySQL / Redis（后续按需接入）
    │ HTTP 内网调用
    ▼
Python FastAPI
    │
    ▼
LangGraph 工作流 ── LangChain 工具 / 模型 / 检索
```

## 为什么 Go 做业务控制面，Python 做 Agent 运行面

- Go 负责身份、租户、权限、业务规则、数据库写入、幂等、审计和对外 API。
- Python 负责自然语言任务编排、工具选择、上下文构造、检索、模型适配、工作流状态与评测。
- 模型不拥有业务权限。即使模型请求调用某个工具，Go 也要重新验证当前用户对目标资源的权限。
- Run ID 是跨服务主键；Request ID 关联单次 HTTP 请求；Event ID 唯一标识事件；Tool Call ID 用于把调用事件与结果关联起来。

## Chat 与 Trace 的实现原则

1. 用户消息与 Agent 回答按会话消息展示；长任务的运行状态与消息内容分开存储。
2. Trace 作为独立事件流，不把日志文本拼进最终回答。
3. 事件字段建议包括 `event_id/run_id/seq/type/node/title/detail/status/duration_ms/tool_call_id/input_summary/output_summary/created_at`。
4. 前期用轮询简化调试，稳定后切 SSE；若需断线恢复，用递增 `seq` 支持 `Last-Event-ID`。
5. 工具参数和返回值应脱敏并设置大小上限，不能把 API Key、完整用户隐私或原始敏感音频文本写进 Trace。

## 生产化待办

- 工具白名单、参数 schema 校验、输出大小限制、超时和熔断。


## 第一阶段运行策略（当前默认）

- Docker Compose 仅启动 Web、Go API、Python Agent。
- Go 使用 SQLite，数据库文件位于容器 `/data/agent_platform.db`，通过 `sqlite_data` volume 持久化。
- Redis 客户端可为空；健康检查和 Run 状态标记均支持 Redis 关闭。
- 后续启用 MySQL 时设置 `DATABASE_DRIVER=mysql` 并提供 `MYSQL_DSN`；启用 Redis 时再增加 Redis 服务、配置及初始化调用。
