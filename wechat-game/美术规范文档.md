## 1. 美术方向

### 1.1 整体风格

游戏采用：

- 低饱和度。
- 柔和配色。
- 扁平化与轻阴影结合。
- 卡通化但保留物件真实结构。
- 清晰的物件轮廓。
- 适合手机屏幕的小尺寸识别。

核心要求：

场景可以杂乱，但物件必须清晰可辨认。

不能为了追求写实细节，让玩家在手机上无法区分物件。

### 1.2 视角

统一使用：

**45° 俯视正交视角。**

要求：

- 不使用明显透视变形。
- 物件角度保持统一。
- 同类物件保持一致的视觉方向。
- 家具和场景物件使用统一视角体系。

### 1.3 第一章配色

第一章属于现代出租屋。

建议主色：

- 米白色。
- 冷灰色。
- 浅木色。
- 少量低饱和蓝色。
- 少量低饱和绿色。

避免：

- 大面积高饱和颜色。
- 过强的荧光色。
- 背景和物件颜色过于接近。

## 2. 画面比例与布局

### 2.1 游戏画幅

目标画幅：

9:16 竖屏。

游戏应适配不同手机分辨率和安全区域。

### 2.2 游戏区域

原策划建议场景区域占屏幕约 60%—65%。

整体布局：

```text
┌────────────────────┐
│      顶部状态区      │
├────────────────────┤
│                    │
│       找寻格        │
│                    │
├────────────────────┤
│                    │
│                    │
│      房间场景       │
│                    │
│                    │
├────────────────────┤
│                    │
│       归位格        │
│                    │
└────────────────────┘
```

具体尺寸由程序根据设计分辨率和安全区域适配，不允许美术直接假设所有设备拥有相同像素尺寸。

## 3. 物件贴图规范

### 3.1 贴图格式

- PNG。
- 透明背景。
- 不带白色底板。
- 不带额外文字说明。
- 不带资源编号水印。
- 物件主体完整。
- 不裁切重要轮廓。

### 3.2 尺寸规范

原策划给出的尺寸参考：

| 物件类型 | 建议尺寸（@2x） |
| -------- | --------------: |
| 大件     |      160—240 px |
| 中件     |       96—140 px |
| 小件     |        64—88 px |
| 极小件   |        56—64 px |

第一章优先使用大、中、小三档。

极小件需要谨慎使用，必须保证手机上可以识别和点击。

### 3.3 点击热区

原策划要求：

- 点击热区不小于 44×44pt。
- 小件热区可以适当外扩。
- 热区不能覆盖大量无关物件。
- 视觉边界与实际点击区域允许存在差异，但不能产生明显误触。

程序需要为每个物件提供独立的点击区域。

### 3.4 阴影和描边

- 物件统一使用 2—3px 深色描边作为参考。
- 阴影轻柔。
- 不使用过重的黑色投影。
- 不同物件的描边粗细必须一致。
- 物件不能因为阴影过大而与其他物件混在一起。

具体描边像素需结合实际导出倍率确认。

---

## 4. 透明底规范

每个物件必须满足：

1. 背景透明。
2. 透明区域没有残留色块。
3. 边缘没有明显白边。
4. 不存在多余画布。
5. 物件主体居中或按统一锚点摆放。
6. 不能把多个独立物件合并成一张图，除非明确作为一个组合物件使用。

禁止：

- 白色背景。
- 棋盘格背景被实际绘制进图片。
- 图片带有文字标签。
- 图片带有 UI 边框。
- 图片带有点击提示图标。

---

## 5. 物件命名规范

文件名统一使用：

```text
ch01_item_物件ID_配色.png
```

示例：

```text
ch01_item_earphone_white.png
ch01_item_earphone_black.png
ch01_item_milk_tea_cup_brown.png
ch01_item_cable_blue.png
ch01_item_coin_gold.png
```

规则：

- 全部小写。
- 使用英文。
- 单词之间使用下划线。
- 章节编号固定两位。
- 同一物件不同颜色使用不同后缀。
- 不使用中文文件名。
- 不使用空格。
- 不使用 final、new、final2 等无意义版本名。

---

## 6. 物件视觉一致性

同一个物件的不同颜色版本必须保持：

- 轮廓一致。
- 视角一致。
- 尺寸一致。
- 光照方向一致。
- 描边一致。
- 阴影一致。

例如耳机：

```text
earphone_white
earphone_black
earphone_pink
```

三种耳机必须让玩家能够判断为同一类物品。

颜色差异不能改变物件的基本识别特征。

## 7. 场景美术规范

### 7.1 场景构成

每关场景由以下部分组成：

```text
场景底板
  ├── 墙面
  ├── 地板
  ├── 门窗
  ├── 家具
  ├── 墙面装饰
  └── 可拾取物件
```

### 7.2 三层视觉结构

| 层     | 内容                     | 可点击 |
| ------ | ------------------------ | ------ |
| 背景层 | 墙面、窗、地板、门       | 否     |
| 家具层 | 床、衣柜、桌、书架、纸箱 | 否     |
| 物件层 | 放置在家具和地面上的物件 | 是     |

### 7.3 生活逻辑

物件摆放必须符合真实生活逻辑。

| 物件类型     | 推荐区域             |
| ------------ | -------------------- |
| 衣物         | 床上、衣柜、衣架附近 |
| 瓶罐         | 桌面、窗台、架子     |
| 书籍         | 书桌、书架、床头     |
| 纸箱         | 墙角、地板、床边     |
| 小型电子物件 | 桌面、床头柜、抽屉   |
| 硬币         | 桌面、沙发、地板缝隙 |

同类物件可以成簇出现，不能完全随机撒在场景里。

### 7.4 遮挡表现

- 被遮挡物件压暗。
- 参考不透明度：55%—65%。
- 仍然保留部分轮廓。
- 不能完全隐藏。
- 不需要美术单独制作暗化版本。
- 暗化效果由程序统一处理。

## 9. 资源交付规范

每个物件交付：

- 原始 PNG。
- 物件 ID。
- 中文名称。
- 配色名称。
- 尺寸档。
- 资源状态。
- 缩略图。

每套场景交付：

- 场景底板。
- 家具资源。
- 墙面装饰资源。
- 场景锚点配置。
- 场景预览图。

---

## 10. 资源验收标准

### 物件验收

- [ ] PNG 格式。
- [ ] 背景透明。
- [ ] 轮廓完整。
- [ ] 视角正确。
- [ ] 尺寸符合要求。
- [ ] 命名符合规范。
- [ ] 物件 ID 已登记。
- [ ] 同款不同色风格统一。
- [ ] 缩小到手机显示尺寸仍能识别。
- [ ] 点击热区可合理设置。

### 场景验收

- [ ] 生活逻辑合理。
- [ ] 视觉层次清楚。
- [ ] 物件不会大面积重叠。
- [ ] 目标物件不会完全被隐藏。
- [ ] 场景主体适配竖屏。
- [ ] 家具和物件资源可复用。

## 11. 第一阶段美术交付原则

第一阶段不要求一次性制作 600+ 张贴图。

先完成第一章 10 关所需资源。

建议顺序：

1. 先制作核心物件。
2. 再制作家具和场景底板。
3. 再补充同款异色。
4. 最后补充干扰物和装饰物。
5. 通过实际游戏画面检查资源表现。

不要在玩法还没有跑通前，大批量制作后续章节美术资源。
