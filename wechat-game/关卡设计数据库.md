# 《一屋百年》关卡设计数据库

- 文档版本：v1.0
- 当前章节：第一章·出租屋的凌晨
- 当前关卡：10 关
- 配置格式：JSON

---

## 1. 设计目标

关卡数据库负责描述每一关的全部内容。

程序不应该知道：

- 第 1 关有哪些物件。
- 第 2 关应该摆多少个纸箱。
- 第 7 关要找几件衣服。
- 第 10 关硬币摆在哪里。

这些内容都应该由 JSON 决定。

程序只负责读取配置并执行统一玩法规则。

---

## 2. 关卡配置字段

| 字段       | 类型   | 说明         |
| ---------- | ------ | ------------ |
| levelId    | string | 关卡唯一 ID  |
| chapterId  | string | 所属章节     |
| title      | string | 场景名称     |
| scene      | string | 场景底板 ID  |
| difficulty | number | 内部难度等级 |
| targets    | array  | 目标物件     |
| rules      | object | 本关玩法参数 |
| items      | array  | 场景物件实例 |
| metadata   | object | 关卡备注     |

---

## 3. 目标配置

```json
{
  "itemId": "earphone",
  "count": 3
}
```

含义：

本关需要找到 3 个耳机。

同一个目标物件可以有多个颜色变体。

第一阶段默认按物件品类计数，不要求玩家寻找指定颜色。

---

## 4. 场景物件配置

```json
{
  "instanceId": "earphone_001",
  "itemId": "earphone",
  "variant": "white",
  "position": {
    "x": 120,
    "y": 300
  },
  "rotation": 0,
  "scale": 1,
  "layer": 2,
  "blocks": [
    "notebook_001"
  ]
}
```

字段说明：

- `instanceId`：本关内唯一的实例 ID。
- `itemId`：引用物件资产数据库。
- `variant`：指定外观变体。
- `position`：场景坐标。
- `rotation`：旋转角度。
- `scale`：缩放比例。
- `layer`：物件层级。
- `blocks`：被该物件遮挡的实例 ID 列表。

## 5. 规则配置

```json
{
  "targetSlots": 2,
  "storageSlots": 4,
  "hintInterval": 12,
  "allowMistake": true,
  "adMode": "mock"
}
```

字段说明：

| 字段         | 说明                      |
| ------------ | ------------------------- |
| targetSlots  | 当前找寻格数量            |
| storageSlots | 当前归位格数量            |
| hintInterval | 提示间隔                  |
| allowMistake | 是否允许错误拾取          |
| adMode       | 广告模式，第一阶段为 mock |

## 9. 遮挡配置规范

遮挡必须明确记录。

例如：

```json
[
  {
    "instanceId": "box_001",
    "blocks": [
      "cable_001",
      "earphone_001"
    ]
  },
  {
    "instanceId": "book_001",
    "blocks": [
      "coin_001"
    ]
  }
]
```

规则：

1. blocks 中必须引用存在的 instanceId。
2. 不能引用自己。
3. 被遮挡物件可以有多个遮挡者。
4. 遮挡者移除后，重新计算可点击状态。
5. 不能出现循环遮挡导致永远无法解锁的情况。
6. 所有目标必须存在至少一条可完成的拾取路径。

## 10. 关卡校验规则

每个 JSON 加载前必须检查：

### 基础检查

- levelId 是否唯一。
- chapterId 是否存在。
- title 是否为空。
- scene 是否存在。
- targets 是否为空。
- items 是否为空。

### 物件检查

- instanceId 是否唯一。
- itemId 是否存在于物件数据库。
- variant 是否存在。
- 资源路径是否有效。
- 坐标是否在有效场景范围内。

### 目标检查

- 目标物件是否存在。
- 目标数量是否大于 0。
- 目标实例数量是否足够。
- 目标格数量是否合理。

### 遮挡检查

- blocks 引用是否有效。
- 是否引用自己。
- 是否存在循环依赖。
- 是否存在永远无法解锁的目标。

### 容量检查

- 归位格数量必须大于 0。
- 关卡必须存在可行的通关路径。
- 不应通过随机生成制造必败关卡。

## 11. 关卡制作流程

```text
确定关卡主题
  ↓
确定目标物件
  ↓
确定干扰物件
  ↓
确定物件数量
  ↓
设计场景布局
  ↓
配置位置和层级
  ↓
配置遮挡关系
  ↓
生成 JSON
  ↓
运行校验工具
  ↓
进入游戏预览
  ↓
人工试玩
  ↓
调整难度
  ↓
通过验收
```

## 12. 后续关卡扩展原则

未来新增普通关卡时：

1. 从物件数据库选择物件。
2. 设计目标数量。
3. 配置场景位置。
4. 配置遮挡关系。
5. 生成 JSON。
6. 校验。
7. 试玩。

原则上不需要修改核心玩法代码。

如果未来增加限时、赝品、漂浮等新机制，则需要扩展对应机制模块，不能只靠普通 JSON 字段假装已经支持。
