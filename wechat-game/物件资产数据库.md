## 1. 数据库设计目标

物件资产数据库是全项目统一的物件信息来源。

它需要解决：

1. 每个物件都有唯一 ID。
2. 中文名称统一。
3. 不同关卡复用同一物件。
4. 同款不同颜色能够区分。
5. 程序可以通过 ID 找到贴图。
6. 美术可以追踪资源制作状态。
7. 关卡配置不需要重复填写物件的基础信息。

物件基础信息放在物件数据库中，物件在具体关卡中的位置、层级和遮挡关系放在关卡数据库中。

---

## 2. 物件 ID 规范

格式：

```text
英文小写 + 下划线
```

示例：

```text
earphone
medicine_bottle
milk_tea_cup
charging_cable
mobile_case
```

规则：

- 全项目唯一。
- 不使用中文。
- 不包含颜色。
- 不包含关卡编号。
- 同一种物件不同颜色使用 variant 区分。
- 不允许因为图片文件名改变而修改物件 ID。

## 3. 物件字段定义

| 字段        | 类型   | 必填 | 说明           |
| ----------- | ------ | ---- | -------------- |
| id          | string | 是   | 物件唯一 ID    |
| name        | string | 是   | 中文名称       |
| category    | string | 是   | 物件分类       |
| era         | string | 是   | 所属年代       |
| size        | string | 是   | 尺寸档         |
| variants    | array  | 是   | 配色或外观变体 |
| sprite      | string | 是   | 主贴图资源路径 |
| thumbnail   | string | 是   | UI 缩略图路径  |
| hitbox      | object | 是   | 点击热区       |
| assetStatus | string | 是   | 资源制作状态   |
| description | string | 否   | 物件说明       |

### 尺寸档

| 值     | 含义   |
| ------ | ------ |
| large  | 大件   |
| medium | 中件   |
| small  | 小件   |
| tiny   | 极小件 |

### 资源状态

| 状态       | 说明       |
| ---------- | ---------- |
| pending    | 待制作     |
| generating | 制作中     |
| review     | 待验收     |
| approved   | 已验收     |
| rejected   | 验收不通过 |

## 6. 物件 JSON 数据格式

建议文件：

`assets/resources/configs/items/items_ch01.json`

示例：

```json
{
  "chapterId": "chapter_01",
  "items": [
    {
      "id": "earphone",
      "name": "耳机",
      "category": "electronics",
      "era": "modern",
      "size": "medium",
      "variants": [
        {
          "id": "white",
          "name": "白色",
          "sprite": "images/items/ch01_item_earphone_white",
          "thumbnail": "images/items/thumb/ch01_item_earphone_white"
        },
        {
          "id": "black",
          "name": "黑色",
          "sprite": "images/items/ch01_item_earphone_black",
          "thumbnail": "images/items/thumb/ch01_item_earphone_black"
        },
        {
          "id": "pink",
          "name": "粉色",
          "sprite": "images/items/ch01_item_earphone_pink",
          "thumbnail": "images/items/thumb/ch01_item_earphone_pink"
        }
      ],
      "hitbox": {
        "width": 56,
        "height": 56
      },
      "assetStatus": "pending"
    }
  ]
}
```

注意：

- JSON 中的资源路径必须与 Cocos 实际资源加载方式一致。
- 不允许使用未经验证的路径。
- 图片资源未制作时，可以先用占位图，但必须明确标记。

## 7. 关卡与资产的关系

物件数据库只负责描述物件本身。

关卡 JSON 负责描述：

- 本关出现哪些物件。
- 每个物件出现几次。
- 每个物件使用哪个变体。
- 每个物件的位置。
- 每个物件的层级。
- 每个物件被谁遮挡。

示例（字段以《数据结构设计文档》为准）：

```json
{
  "id": "earphone_001",
  "itemId": "earphone",
  "variantId": "white",
  "position": { "x": 120, "y": 900 },
  "rotation": -6,
  "scale": 1.313,
  "layer": 1,
  "zone": "pile",
  "blocking": ["notebook_001"]
}
```

`blocking` 表示“谁挡住我”：`notebook_001` 被拿走后，`earphone_001` 才能点击。

## 7.1 图标贴图与轮廓

- 贴图：`web/public/sprites/<物件ID>__<变体ID>.webp`，游戏里实际显示的就是这些图。
- 轮廓：`web/src/data/item_masks.json`（每个物件一张 48×48 位图），关卡生成、配置校验、运行时点击判定都用它判断遮挡。

两者都由 `npm run export:icons` 生成。新增物件、替换图标或接入正式美术后，先运行它，再运行 `npm run gen:levels` 重新生成关卡。

当前 Web 原型用 emoji 作为占位图标，多变体物件（如白/黑/粉耳机）在导出时按变体颜色着色，玩家能看出同款不同色；正式美术按变体出图后替换即可。

## 9. 资产管理规则

每次新增物件必须：

1. 分配唯一 ID。
2. 确定中文名称。
3. 确定所属分类。
4. 确定年代。
5. 确定尺寸档。
6. 登记配色变体。
7. 确定贴图路径。
8. 登记制作状态。
9. 完成视觉验收。
10. 再允许关卡引用。

禁止：

- 关卡直接引用未登记物件。
- 两个物件共用同一个 ID。
- 未验收资源进入正式关卡。
- 通过修改图片文件名改变物件身份。
