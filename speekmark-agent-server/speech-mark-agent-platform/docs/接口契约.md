# API 接口契约 v1

基础路径：`/api/v1`。前端通过 `/api` 访问，由 Vite/Nginx 将其改写为 `/api/v1`。所有 Go API 成功响应统一为 `{ "data": <业务数据>, "request_id": "..." }`；前端 Axios 拦截器负责解包 `data`。错误响应为 `{ "error": { "code": "...", "message": "..." }, "request_id": "..." }`。

## 健康检查

- `GET /health/live`：进程存活，不检查依赖。
- `GET /health/ready`：检查 SQLite；失败返回 HTTP 503，响应中的 `redis` 为 `disabled`。
- Agent：`GET /health/live`、`GET /health/ready`。

## Go API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/v1/agent/dashboard` | 工作台统计 |
| GET | `/api/v1/agent/runs?page=1&page_size=20&status=&keyword=` | 分页查询运行记录 |
| POST | `/api/v1/agent/runs` | 创建 Agent Run |
| GET | `/api/v1/agent/runs/{run_id}` | 查询 Run 详情 |
| GET | `/api/v1/agent/runs/{run_id}/trace` | 查询执行轨迹 |
| POST | `/api/v1/agent/runs/{run_id}/cancel` | 请求取消 Run |
| GET | `/api/v1/agent/approvals?status=pending` | 审批列表 |
| POST | `/api/v1/agent/approvals/{approval_id}/approve` | 批准 |
| POST | `/api/v1/agent/approvals/{approval_id}/reject` | 拒绝 |
| GET | `/api/v1/agent/knowledge` | 知识文档列表（占位） |
| POST | `/api/v1/agent/knowledge/search` | 知识检索（占位） |

### 创建 Run

请求：

```json
{"input":"解释切分边界错误的判定标准","mode":"balanced"}
```

`mode` 可选 `fast`、`balanced`、`careful`。响应业务数据：

```json
{"run_id":"run_xxx","status":"queued","started_at":"2026-10-22T06:00:00Z"}
```

### Run 详情

```json
{
  "run_id":"run_xxx","input":"...","mode":"balanced","status":"succeeded",
  "final_answer":"...","error":"","duration_ms":123,"steps":3,"tools":1,"tokens":0,
  "started_at":"2026-10-22T06:00:00Z","finished_at":"2026-10-22T06:00:01Z"
}
```

状态：`queued`、`running`、`succeeded`、`failed`、`cancelled`、`waiting_approval`。

### Trace

```json
{
  "run_id":"run_xxx",
  "events":[{
    "event_id":"evt_xxx","run_id":"run_xxx","seq":1,"type":"node.completed",
    "node":"classify","title":"识别任务意图","detail":"...","status":"succeeded",
    "duration_ms":12,"tool_call_id":null,"created_at":"2026-10-22T06:00:00Z"
  }]
}
```

Trace 只存放可审计的执行事件、工具调用摘要、耗时和错误；禁止将隐藏推理链作为日志输出。

## Python Agent 内部 API

本地开发时 Go 服务通过 `http://localhost:8000` 调用 Python Agent：

- `POST /v1/runs`：`{"run_id":"run_xxx","input":"...","mode":"balanced"}`
- `GET /v1/runs/{run_id}`
- `GET /v1/runs/{run_id}/trace`

Python 使用同一 `run_id`，便于 Go、Agent、日志和 Trace 关联。真实生产系统还应透传 `X-Request-ID` 与 `traceparent`，并校验内部服务身份。

## 统一约定

- 时间统一 ISO 8601 / RFC 3339，推荐 UTC 存储，前端本地展示。
- ID 使用不透明字符串，不要让前端依赖数据库自增 ID。
- 列表默认 `page=1`、`page_size=20`，最大 `page_size=100`。
- 所有请求应可携带 `X-Request-ID`；服务端未收到时生成。
- 所有写操作必须具备身份校验、资源授权、幂等策略和审计记录（当前学习骨架尚未完成登录认证）。
