# 术语表（前端视角速查）

> 面向前端出身的你，用一句话解释 + 尽量给个前端能类比的说法。看文档遇到生词回来查。

## RAG 相关

- **RAG（检索增强生成）**：先从你的文档里"查资料"，再把资料喂给大模型作答。
  类比：不是让模型凭记忆答题，而是开卷考试，先翻书再写答案。

- **文档解析（Parsing）**：把 PDF/Word 等文件里的内容提取成纯文本。
  类比：从富文本里 `innerText` 把文字抠出来。

- **分块（Chunking）**：把长文档切成一小段一小段，便于检索。
  类比：把一篇长文章按段落拆成数组 `string[]`，每段单独处理。

- **Embedding（向量化）**：把一段文字转成一串数字（向量），语义相近的文字向量也相近。
  类比：给每段文字算一个"语义指纹"（一个固定长度的数字数组）。

- **向量维度（Dimension）**：这串数字的长度。bge-m3 是 1024，即每段文字 → 1024 个数字。
  注意：入库和查询必须用同一维度，否则对不上。

- **向量库（Vector DB，如 Milvus）**：专门存向量、并能快速"找最相似的若干条"的数据库。
  类比：一个支持"按语义相似度排序查询"的特殊数据库，而不是按字段精确匹配。

- **检索 top-k**：查询时返回最相似的 k 条。k=4 就是取最相关的 4 段。

- **重排（Rerank）**：对检索回来的若干段，用更强的模型重新打分排序，把最相关的提前。
  类比：先粗筛一批候选，再精排序。

- **幻觉（Hallucination）**：模型一本正经地编造资料里没有的内容。RAG + 强约束 Prompt 是为了压制它。

## Agent 相关

- **Agent（智能体）**：以大模型为"大脑"、能自己决定下一步做什么、会调用工具的程序。
  类比：不只是回答，还能"自己调接口、自己分步骤办事"的助手。

- **工具调用（Tool / Function Calling）**：让模型在回答过程中调用你提供的函数（查数据库、算数等）。
  类比：模型说"我需要调用 `getSensorSpec('X')`"，你的后端执行后把结果再给它。

- **任务规划（Planning）**：模型把复杂任务拆成多步并按顺序执行。

- **记忆（Memory）**：让 Agent 记住多轮对话的上下文。短期=本轮会话，长期=跨会话。本项目用 Redis 存。

- **ReAct**：一种 Agent 范式——"思考(Reasoning) → 行动(Action/调工具) → 观察结果"循环，直到得出答案。

## 框架 / 工具

- **LangChain**：把"加载/分块/向量化/检索/调模型"等 RAG 组件封装好的 Python 框架，少造轮子。

- **LangGraph**：LangChain 家族里做"有状态、多步骤 Agent 编排"的库，用"状态图"描述流程。
  类比：给 Agent 的执行流程画一张状态机/流程图。

- **Flask**：Python 的轻量 Web 框架。类比：Python 版的 Express。

- **Milvus**：开源向量数据库。**Redis**：你熟的内存数据库，这里兼做缓存/会话记忆。

- **SSE（Server-Sent Events）**：服务器向浏览器单向持续推送数据，用来做"逐字输出"的流式效果。
  类比：你前端已经可能用过的 `EventSource`。

## 微调相关（后期才用）

- **微调（Fine-tuning）**：在特定数据上继续训练模型，让它更懂你的领域。
- **LoRA / QLoRA**：轻量微调方法，只训练一小部分参数，省算力，入门首选。
- **SFT（指令微调）**：用"指令→期望回答"的样本对训练模型。
