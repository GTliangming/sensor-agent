# 《一屋百年》关卡设计数据库

- 文档版本：v1.1（2026-11-11 与 Web 原型 `web/` 对齐）
- 当前章节：第一章·出租屋的凌晨
- 当前关卡：10 关
- 配置格式：JSON，字段以《数据结构设计文档》为准
- 关卡文件：`web/src/data/levels/level_001.json` ~ `level_010.json`，由 `npm run gen:levels` 生成

> v1.1 变更摘要：字段名统一为《数据结构设计文档》的写法；遮挡字段由 `blocks`（我挡住谁）改为 `blocking`（谁挡住我）；
> 物品区改为一整块逐层叠放，物件总数增加到 32–66 个；遮挡关系改为按图标真实轮廓自动计算。

---

## 1. 设计目标

关卡数据库负责描述每一关的全部内容。

程序不应该知道：

- 第 1 关有哪些物件。
- 第 2 关应该摆多少个纸箱。
- 第 7 关要找几件衣服。
- 第 10 关硬币摆在哪里。

这些内容都应该由 JSON 决定。程序只负责读取配置并执行统一玩法规则。

## 2. 关卡配置字段

| 字段             | 类型   | 说明                                   |
| ---------------- | ------ | -------------------------------------- |
| id               | string | 关卡唯一 ID，如 `level_001`            |
| chapterId        | string | 所属章节                               |
| levelNumber      | number | 关卡序号                               |
| name             | string | 场景名称                               |
| sceneId          | string | 场景 ID                                |
| difficulty       | number | 内部难度等级                           |
| teaching         | string | 开局提示条显示的教学内容               |
| requiredWrong    | number | 必要失误数，生成时算出，用于星级计算   |
| designResolution | object | 生成时参照的设计分辨率，1080×2340      |
| objectives       | array  | 目标物件                               |
| itemInstances    | array  | 场景物件实例                           |
| gridConfig       | object | 找寻格、归位格、广告配置               |
| hintConfig       | object | 提示配置                               |
| completionConfig | object | 通关配置                               |

## 3. 目标配置

```json
{ "itemId": "earphone", "requiredCount": 3, "displayVariant": "white" }
```

本关需要找到 3 个耳机。目标按物件品类（`itemId`）计数，不区分颜色变体；`displayVariant` 只决定找寻格里显示哪个外观。

一种目标占一个找寻格，格子上显示“剩余数量 / 初始总数量”。

---

## 4. 场景物件配置

```json
{
  "id": "earphone_001",
  "itemId": "earphone",
  "variantId": "white",
  "position": { "x": 120, "y": 900 },
  "rotation": -6,
  "scale": 1.313,
  "layer": 1,
  "zone": "pile",
  "blocking": ["notebook_002", "key_001"]
}
```

字段说明：

- `id`：本关内唯一的实例 ID。
- `itemId`：引用物件资产数据库。
- `variantId`：外观变体。
- `position`：图标中心坐标，设计像素，原点在左下角，Y 轴向上。
- `rotation`：旋转角度，逆时针为正。
- `scale`：缩放。同一关内所有物件显示为同一尺寸，`scale = 本关图标尺寸 / 物件原始宽度`。
- `layer`：层级，数字越大越靠上。
- `zone`：所在区域，第一章所有关卡都是整块物品区 `pile`。
- `blocking`：**遮挡当前物件的实例 ID 列表（谁挡住我）**。列表里的物件全部被拿走后，当前物件才能点击。

## 5. 玩法参数配置

```json
{
  "gridConfig": {
    "targetSlots": { "baseCount": 2, "maxCount": 2 },
    "collectionSlots": { "capacity": 4 },
    "adConfig": { "enabled": true, "simulated": true }
  },
  "hintConfig": { "enabled": true, "autoHintSeconds": 12, "maxFreeUses": 3, "highlightDuration": 2.5 },
  "completionConfig": { "requireAllObjectivesCompleted": true, "nextLevelId": "level_002" }
}
```

| 字段                          | 说明                                              |
| ----------------------------- | ------------------------------------------------- |
| targetSlots.baseCount/maxCount | 找寻格数量，第一章等于目标种类数，暂不做广告扩格 |
| collectionSlots.capacity      | 归位格容量，第一章统一为 4                        |
| adConfig                      | 第一阶段只用模拟广告                              |
| hintConfig.autoHintSeconds    | 无操作多少秒后自动提示，0 为关闭                  |
| hintConfig.maxFreeUses        | 每局免费主动提示次数                              |
| hintConfig.highlightDuration  | 提示闪烁时长（秒）                                |

- “必要失误”= 不看广告通关时至少要放进归位格的干扰物数量，始终小于归位格容量 4，写在关卡 JSON 的 `requiredWrong` 字段里。星级按超出这个数的失误计算。

- 每关干扰物 14 种，避免同一图标在一关里重复太多次。
- 具体数值以生成的关卡 JSON 为准，重新生成后可用 `npm run gen:levels` 的输出核对本表。

## 7. 关卡生成方式

第一章关卡由 `web/scripts/generate-levels.ts` 按固定种子生成，重复运行结果一致。规格写在 `web/scripts/level-specs.ts`。

1. **铺物品堆**（`pile-geometry.ts`）：按网格逐层摆放位置与角度，先用方块近似估算遮挡。
2. **分配身份**（`level-generator.ts`）：决定哪些格子放目标、哪些放干扰物。被压住的目标，其上方物件只能是目标或本关的“门槛干扰物”，门槛数量等于必要失误。目标尽量分散，物品区 3×3 宫格里至少 5 格有目标。
3. **按真实轮廓重算遮挡**：用 `web/src/data/item_masks.json`（`npm run export:icons` 导出的图标轮廓）计算 `blocking`。上层图标本体实际盖住下层图标本体至少 3 个采样点才算遮挡。求出的必要失误写入 `requiredWrong`。
4. **校验**：结构、引用、无环、可完成性、遮挡与轮廓一致，任何一项不通过就换种子重试。

运行时的点击判定读同一份轮廓，所以“看起来被压住”“点不动”“校验通过”三者一致。

## 8. 遮挡规则

`blocking` 记录“谁挡住我”：

```json
{ "id": "coin_003", "blocking": ["cushion_002", "sock_001"] }
```

含义：`coin_003` 被 `cushion_002` 和 `sock_001` 压住，两者都被拿走后 `coin_003` 才能点击。

规则：

1. `blocking` 中必须引用本关存在的实例 ID。
2. 不能引用自己。
3. 一个物件可以被多个物件遮挡，全部移走才解锁。
4. 只能被层级更高的物件遮挡，因此不会出现循环遮挡。
5. 必须与图标真实轮廓一致：画面上压住了才能写进去，没压住就不能写。
6. 所有目标必须存在一条不看广告也能完成的拾取路径。

不要手改 `blocking`。调整布局应改规格后重新生成。

## 9. 关卡校验规则

`npm run validate:configs` 对每个关卡检查：

### 基础检查

- 关卡 ID 唯一，chapterId 与章节一致，sceneId 存在，nextLevelId 有效。
- objectives、itemInstances 非空。

### 物件检查

- 实例 ID 唯一。
- itemId 存在于物件数据库，variantId 属于该物件。
- scale 大于 0，layer 为非负整数，坐标在画布内，zone 存在于场景。

### 目标检查

- 目标物件不重复，数量 ≥ 1，场景中实例数量足够。
- 目标种类数不超过找寻格数量。

### 遮挡检查

- blocking 引用有效、不引用自己、无循环。
- blocking 与图标真实轮廓一致。

### 可完成性检查

- 用真实玩法逻辑模拟一条最少失误的点击顺序，必须能通关。
- 必要失误数必须小于归位格容量，即不依赖救场也能通关。

## 10. 关卡制作流程

```text
写关卡规格（目标、干扰物、物品堆形状、必要失误、埋住比例）
  ↓
npm run gen:levels（生成并自动校验）
  ↓
npm run dev 试玩
  ↓
调整规格或换种子
  ↓
npm test、npm run e2e 回归
  ↓
通过验收
```

换了图标或正式美术资源后，先运行 `npm run export:icons` 更新轮廓，再重新生成关卡。

---

## 11. 后续关卡扩展原则

未来新增普通关卡时，只需新增关卡规格并重新生成，原则上不修改核心玩法代码。

如果未来增加限时、赝品、漂浮等新机制，需要扩展对应机制模块，不能只靠普通 JSON 字段假装已经支持。
