## 一、搭完骨架你会得到什么（验收）

- `backend/` 一个最小 Flask 服务：有一个 `/api/chat` 的 SSE 接口，收到问题后**直接调 DeepSeek**流式返回（先不检索）
- `frontend/` 一个 Vite + React + TS 工程：两个空页面（文档管理页 / 提问页）+ 路由切换 + 一个能发 SSE 请求的输入框

- `.env.example` + `.gitignore`：Key 的占位模板，且保证敏感文件不进 git
- ✅ 总验收：**前端输入问题 → 后端调 DeepSeek → 答案在前端逐字流式显示**。这条管子通了，阶段 0 就完成。

> 注意：阶段 0 **不写** ingest.py / rag.py 的真实逻辑，不连 Milvus。那是 `01` 文档「阶段 1」的事。
> 骨架阶段只验证"环境 + 网络 + Key + 流式"没问题。

> **为什么后端要分层**：`01` 文档里给的是单文件 `app.py`，适合"一眼看懂"，但真实项目请求会越堆越多，

> `services/chat_service.py`，路由层一行不用动。

## 四、后端骨架（backend/）—— 分层结构

> 分层约定（请求自上而下流动）：
> **api/**（路由层：校验参数、拼 SSE 响应，不写业务）→ **services/**（业务层：真正的逻辑）→
> **clients/**（外部依赖层：封装 DeepSeek 等客户端）→ **schemas/**（数据契约：请求校验）。

### 4.1 建虚拟环境 + 装依赖

```bash

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install flask flask-cors python-dotenv openai pydantic
pip freeze > requirements.txt
```

> 阶段 0 需要：`flask`（Web）、`flask-cors`（跨域）、`python-dotenv`（读 .env）、
> `openai`（DeepSeek 走 OpenAI 兼容接口）、`pydantic`（请求参数校验）。LangChain/Milvus 等到阶段 1 再装。

### 4.3 `config.py`（配置类）

用一个 `Config` 类集中管理配置，并提供 `validate()` 在用到外部服务前校验必填项（缺 Key 早失败）：

```python
import os
from dotenv import load_dotenv

load_dotenv()


class Config:
    HOST = os.getenv("HOST", "127.0.0.1")
    PORT = int(os.getenv("PORT", "5000"))
    DEBUG = os.getenv("FLASK_DEBUG", "1") == "1"
    CORS_ORIGINS = os.getenv("CORS_ORIGINS", "http://localhost:5173").split(",")

    DEEPSEEK_API_KEY = os.getenv("DEEPSEEK_API_KEY")
    DEEPSEEK_BASE_URL = os.getenv("DEEPSEEK_BASE_URL", "https://api.deepseek.com")
    DEEPSEEK_MODEL = os.getenv("DEEPSEEK_MODEL", "deepseek-flash")

    def validate(self) -> None:
        if not self.DEEPSEEK_API_KEY:
            raise RuntimeError("缺少 DEEPSEEK_API_KEY，请在 backend/.env 中配置")


config = Config()
```

### 4.4 应用工厂与分层（app/）

**`app/__init__.py` — 应用工厂**：创建 app、绑定扩展、注册蓝图与错误处理。这是 Flask 真实项目的标准写法。

```python
from flask import Flask, jsonify
from config import config
from .extensions import cors
from .api import register_blueprints


def create_app() -> Flask:
    app = Flask(__name__)
    app.config.from_object(config)
    cors.init_app(app, resources={r"/api/*": {"origins": config.CORS_ORIGINS}})
    register_blueprints(app)
    return app
```

**`app/api/chat.py` — 路由层**：只校验参数、把 service 的生成器包成 SSE 响应。

```python
from flask import Blueprint, Response, abort, request
from pydantic import ValidationError
from ..schemas.chat import ChatRequest
from ..services.chat_service import stream_answer

chat_bp = Blueprint("chat", __name__, url_prefix="/api")


@chat_bp.post("/chat")
def chat():
    try:
        payload = ChatRequest.model_validate(request.get_json(silent=True) or {})
    except ValidationError as e:
        abort(400, description=f"参数错误：{e.errors()[0]['msg']}")
    return Response(stream_answer(payload.question), mimetype="text/event-stream")
```

**`app/services/chat_service.py` — 业务层**：阶段 0 直接调 DeepSeek；**阶段 1 的 RAG（向量化→检索 Milvus→拼 Prompt）就加在这个函数里，路由层不用动。**

```python
from typing import Iterator
from config import config
from ..clients.llm import get_llm_client


def stream_answer(question: str) -> Iterator[str]:
    client = get_llm_client()
    stream = client.chat.completions.create(
        model=config.DEEPSEEK_MODEL,
        messages=[{"role": "user", "content": question}],
        stream=True,
    )
    for chunk in stream:
        delta = chunk.choices[0].delta.content or ""
        if delta:
            yield f"data: {delta}\n\n"
    yield "data: [DONE]\n\n"
```

> 另外三个小文件：`app/extensions.py`（`cors = CORS()`，晚绑定避免循环导入）、
> `app/clients/llm.py`（`get_llm_client()` 用 `lru_cache` 建单例 + `config.validate()`）、
> `app/schemas/chat.py`（pydantic 的 `ChatRequest`，校验 question 非空）。

**`wsgi.py` — 入口**（注意：包名已是 `app/`，入口不能再叫 `app.py`，否则冲突）：

```python
from app import create_app
from config import config

app = create_app()

if __name__ == "__main__":
    app.run(host=config.HOST, port=config.PORT, debug=config.DEBUG)
```

> ⚠️ `/api/chat` **没有鉴权**——阶段 0 只在本机 `localhost` 跑没问题；一旦要对外部署，必须加访问控制，
> 别把一个能直接消耗你 DeepSeek 额度的接口裸露在公网。

- ✅ 产出：`python wsgi.py`（或 `flask --app wsgi run --port 5000`）起服务后，
  `curl -N -X POST localhost:5000/api/chat -H "Content-Type: application/json" -d '{"question":"你好"}'` 能看到逐段返回；
  `curl localhost:5000/api/health` 返回 `{"status":"ok"}`。

### 5.2 `src/api/chat.ts`（封装 SSE 请求）

> 后端用的是 `POST + text/event-stream`，浏览器原生 `EventSource` 只支持 GET，所以这里用
> `fetch` + 手动读流（`ReadableStream`）来接收逐字输出。

```typescript
export async function askChat(question: string, onDelta: (text: string) => void) {
  const resp = await fetch("http://localhost:5000/api/chat", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ question }),
  });
  const reader = resp.body!.getReader();
  const decoder = new TextDecoder();
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    decoder.decode(value).split("\n\n").forEach((line) => {
      if (line.startsWith("data: ")) {
        const data = line.slice(6);
        if (data && data !== "[DONE]") onDelta(data);
      }
    });
  }
}
```

## 六、docker-compose.yml（Milvus + Redis）

> 阶段 0 可以**先跳过**这步（流式链路不依赖 Milvus）。但建议顺手起一次，确认本机 Docker 环境没问题，
> 省得阶段 1 接 RAG 时才发现 Docker 跑不起来。

- Milvus 用**官方 standalone 版**，它会额外带 `etcd` 和 `minio` 两个附属容器（正常现象，别慌）。
- Redis 阶段 0 可选，先起着占位。
- 具体 compose 内容建议直接用 Milvus 官方给的 `standalone` 模板，再加一个 redis 服务块。
- ✅ 产出：`docker compose up -d` 后，Milvus 的 `19530` 端口可连通，Redis 的 `6379` 可连通。

## 八、推荐的跑通顺序（最快看到效果）

1. 先搞后端那条：建 venv → 装依赖 → 填 `.env` → `python wsgi.py` → 用 `curl` 验证能流式返回
2. 再搞前端：`npm create vite` → 装 router → 写 `chat.ts` 和两个页面 → `npm run dev` → 页面上验证逐字输出
3. 最后(可选)起 Docker：`docker compose up -d`，确认 Milvus/Redis 端口通
4. 全绿 → 阶段 0 完成，进入 `01` 文档的「阶段 1：接入 RAG」

> 心法：**一次只接一段管子，接完立刻验证**。先确认 DeepSeek 能流式回话，再碰 RAG，
> 这样一旦出问题，你能立刻定位是哪一段断的，而不是一堆东西搅在一起排查。
